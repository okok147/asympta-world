# World Circles v1

Routes are under `/v1/circles/{circleID}`. Circle IDs and contribution IDs are lowercase 32-character hexadecimal identifiers. Circle ID is client-generated to make create retries recoverable. Each request uses the existing installation bearer credential. The Worker derives a circle-specific member identity and never exposes the presence/profile identity or token.

Responses use epoch milliseconds for dates. Optional fields may be null or omitted. Non-success responses are `{"error":"code"}`.

- Member: `{id,name,style?}`, with an opaque string ID. Circle: `{id,title,me,memberCount,canInvite}`. Moment: `{id,author,text,createdAt,region,hasPhoto,photoDescription,replyCount,reactionCount,reacted,owned}`. Reply: `{id,author,text,createdAt,owned}`. Activity: `{momentID,replyID,author,text,createdAt}`.
- POST `/create` with `{title,name}` and POST `/join` with `{secret,name}` return Circle. Owner GET `/invite` and POST `/invite/rotate` return `{code}`, formatted as `circleID.secret` (32 hex each). JOIN requires the secret even when the circle ID is known.
- GET circle root returns `{circle,moments,activity}` for a member, newest first. Activity consists of unread replies to this member's visible moments. GET `/moments/{momentID}` returns `{moment,photo,replies}`. Photo is optional base64 JPEG. Replies oldest first.
- POST `/v1/circles/inbox` (outside the per-circle routes) accepts `{circleIDs:[id,…]}` with one to eight explicit IDs and the same installation bearer. The Worker deduplicates IDs and checks each circle with its own scoped identity. It returns `{groups:[{circle,activity,hasMore}],partial}` with at most 32 unread previews per accessible circle. Missing, closed and inaccessible circles are omitted uniformly. `partial` marks temporary read failures. Preview reads change no read boundary and return no photo or full feed.
- POST `/moments` with `{id,text,region?,photo?,photoDescription?}` creates one Moment per ID and returns `{id}`. Text is up to 480 characters, photo description up to 140, one photo up to 160 KB decoded. A caption or a described photo is required. Optional region uses `"x:y"` for the existing coarse map cell. Sharing the area is off by default. Server bounds image type, dimensions and request bytes, strips metadata and associates it with the post.
- POST `/moments/{momentID}/replies` with `{id,text}` (up to 240 chars) returns `{id}`. POST `/moments/{momentID}/reaction` with `{active:Bool}` sets desired state, returns `{ok:true}`. POST `/read` with `{momentID,through}` marks replies already seen by the author of that moment, returns `{ok:true}`.
- POST `/moderate` with `{kind:"moment"|"reply",target,action:"report"|"block"|"remove"}` returns `{ok:true}`. Target is contribution ID. Report hides for the reporter and goes to the host queue. Block hides both directions and applies on all reads and writes that target the blocked person. Remove is for the contributor or host. GET `/reports` (host only) returns `{reports:[{kind,target,author,text,createdAt,reportCount}]}`, where text is the reported text. POST `/resolve` with `{kind,target}` dismisses pending reports while preserving the reporter's own hidden state. For reversible blocking, GET `/blocks` returns `{members:[Member]}` and POST `/unblock` with `{id}` returns `{ok:true}`.
- Reports accept an optional reason `harassment`, `spam`, `privacy` or `other`. Host GET `/reports/{kind}/{target}` requires an unresolved report and returns `{report,photo?,photoDescription?}`. The report carries a reason-count dictionary, without reporter identity. Reply review never includes the parent photo.
- Owner-only GET `/members` returns `{members:[Member]}`. POST `/members/remove` with `{id}` removes the target member and their contributions and rotates the invitation. It cannot remove the owner.
- POST `/leave` removes the authenticated member's contributions in this circle, transfers ownership to the next member when necessary and returns `{ok:true}`. No other circle, aura, or personal-store deletion.
- POST `/appearance` with `{style}` selects the caller’s seal for this circle. Styles are `clay`, `saffron`, `tide` and `dusk`. Visible member and author records carry the current choice.
- Map geography and peer presence stay on existing endpoints. World Circles is an invite-only TestFlight feature with no public directory or outbound push. Activity is read from the service inside the circle. Social data is isolated from the existing personal journal and cloud abilities.
